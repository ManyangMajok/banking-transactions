## Explain the implementation — about two minutes

1. **Layers:** React and Inertia provide forms and confirmed balances. Laravel Form Requests validate input; controllers call services; MySQL stores accounts, transactions and loans. Show `app/Services/BankingService.php` rather than reading all the code.
2. **Money:** `MoneyParser.php` converts decimal strings into integer cents. KES 10,000 is stored as 1,000,000 cents, avoiding floating-point rounding in financial arithmetic.
3. **All-or-nothing writes:** a database transaction groups the debit, credit and history. If any part fails, every change rolls back. A test deliberately interrupts a transfer after the debit to verify this.
4. **Simultaneous requests:** row locks prevent two withdrawals from spending the same balance. Accounts are locked in ascending ID order to reduce deadlocks. Separate-process tests exercise this; clicking slowly in a browser cannot prove concurrency safety.
5. **Retries:** each intended operation has a UUID key. Repeating the same key and details returns the original result; changing the details with that key is rejected. This prevents duplicate money movement when retrying an uncertain response. A newly opened operation is a different request.
6. **History:** soft deletion retains account relationships and transaction references. The reconciliation command independently sums movements and compares the result with stored balances, including archived accounts.
